## How a request flows through what was built today

1. Eval: dataset sample -> production preprocessing (2560 px JPEG) -> `showme.core` grounding (Spark minimal, prompt v1) -> post-processing -> scored prediction in `predictions.jsonl`.
2. Optional SAM: model box -> SAM 3.1 -> agreement gate (IoU, contains point, size cap) -> outline or box fallback; the click point never changes.
3. Optional verifier (off by decision): crop around the box -> yes/no re-check -> would downgrade to `unsure`.
4. Browser (Day 4 wiring next): screenshot -> tesseract worker lines -> pattern matches -> solid blocks on canvas -> `RedactedImage` -> API.

## 5 likely judge or interviewer questions

1. "Why confidence is not trusted?" - On 1,172 held-out screens its AUROC was 0.622, near coin-flip; the model even returned values above 1.0. So confidence is logged for eval but never shown or gated on.
2. "Why SAM cannot change click accuracy?" - The click point comes only from the grounding model; SAM receives the finished box and may only replace the rectangle with an outline when it agrees. Accuracy is identical by construction; only highlight shape changes.
3. "Is 90.7% your real accuracy?" - It is the held-out ScreenSpot-v2 number at production preprocessing, and the same page reports Pro at 63.7% and honesty at 60.5%. The weakest number ships next to the best.
4. "What did Wonder buy you?" - +3.0 points on Pro for 2.9x the cost. Not the default; escalation not built (D22).
5. "Where does redaction fail?" - Pattern recall on clean text is 40/40, but names and free text inside fields are not caught by patterns; that is why the review screen is mandatory and cannot be skipped.
