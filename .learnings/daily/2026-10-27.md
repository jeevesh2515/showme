## How a request will flow (design, not built)

1. User adds screenshot + goal in browser (`/app`).
2. Browser OCR (tesseract.js, self-hosted) + regex finds email/phone/card/postcode/IBAN/digit-runs, covers them with solid blocks.
3. Mandatory review screen: user taps/brushes anything else private. No skip. Only the reviewed, canvas-re-encoded JPEG (max 1920 px, EXIF stripped) can become a `RedactedImage`.
4. `POST /v1/step`: backend calls `muse-spark-1.3` (`minimal`, strict JSON schema, 0-1000 grid), clamps/fixes coordinates, applies honesty gate, returns one instruction + box. Box shows immediately.
5. `POST /v1/refine`: backend prompts `sam-3.1` with the model box; outline replaces box only if SAM agrees (IoU >= 0.5, contains model point, area <= 25%). SAM never moves the click.
6. User acts, uploads next screenshot. History travels as text only. Optional Share stores only redacted images, hashed token, 7-day expiry.

## The loop engineering (how the 8.5 gate works)

1. Score: 5 independent reviewers (3 internal subagents on disjoint briefs: docs consistency, privacy/security, eval evidence; plus Spark and Wonder via the Meta API as judge-models) each score 0-10 with findings at `file:line`.
2. Gate: score < 8.5 = not accepted. No averaging away a blocker: any blocker finding must be fixed or explicitly rejected with a reason recorded here.
3. Fix: smallest doc/code change per finding (ponytail review), then `scripts/score_gate.py` re-scores the mechanical facts (placeholders gone, IDs defined, links resolve, `.env` untracked, git remote live...).
4. Repeat until PASS. `docs/SCORE.md` is generated by the script; a human never edits the number. History appends to `.learnings/score-history.json` so a later day cannot silently lower the bar.
5. Human input enters at exactly two points: founder decisions (today: D14) and rejecting a finding (today: list below).
